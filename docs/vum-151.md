# Build 0.151 — VUM 2 / physical mapping foundation

The physical view registry assigns a monotonically increasing identity to every section, independently of its Windows HANDLE. A contiguous guest span can be resolved to a generation, byte offset and length; scattered and hole-containing ranges cannot be treated as one contiguous buffer. A section's physical identity survives changes of virtual mapping and is removed at section teardown. Exact alias projection works with partial views.

The bounded experimental backend (VICTORY_VUM_PHYSICAL=1; off by default) allocates up to 128 MiB of committed candidate segments, at most 32 MiB each, from physical page allocations. The rest of a pool remains in the previous SEC_RESERVE section, with lazy commitment. The existing page-number table and run splitting preserve guest-visible addresses and page numbers. A rejected candidate falls back to the old path. VICTORY_VUM_PHYSICAL_MB sets the separate candidate and native charge limits (max 512 MiB). The native heap/buffer is opened only on first actual use. Compatible contiguous views share one buffer keyed by section generation and use physical offsets. The physical buffer survives virtual view removal and is retained for recorded work. Completed declared writes publish their captured physical ranges to current aliases instead of assuming the recorded virtual address still represents those bytes.

Important: the direct pool path is experimental and not ready for ordinary gameplay. A remap invalidates cached virtual shadow associations and stale native resolutions, but already recorded native GPU addresses and persistent heap descriptors cannot yet be retargeted safely. Cross-alias CPU/GPU dependency tracking, dynamic writes and textures are also not complete. Do not enable the experiment in the normal benchmark yet. Default rendering continues to use VUM1 and the existing pool copies. No bulk commitment or extra mapped memory is introduced by default. This is a partial implementation of VUM2, not a claimed performance optimization or complete pool conversion. Next required work: submission-time remap/version validation, descriptor rebinding and physical dependency tracking. Windows compilation and graphics correctness not verified. New VUM 2 log distinguishes native opens, reuse, bindings and bound remaps.
