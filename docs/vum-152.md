# Build 0.152 — VUM physical mapping validation and dependencies

This phase replaces physical alias projection's full view-map traversal with the existing 64 KiB physical page index. Exact byte intervals are joined per section generation. Direct physical GPU write declarations are captured in the flight line and retained through relay landing. CPU consumers resolve those declarations against the current aliases, including aliases made after recording. Card-step promotion is conservatively disabled while such writes are in flight.

Persistent heap SRV/UAV/CBV factories capture their actual physical binding (section, generation, guest span, offset), rather than resolving from a possibly changed guest address. The submission path can rebind stale persistent slots after settling older flights. A recorded shadow or persistent heap binding that changes before native submission is rejected explicitly instead of executing an obsolete GPU address. Final validation holds the mapping read lock only during command submission, never through a native-fence or relay wait. An exact by-address alignment fallback no longer treats nonzero shared backing offsets as zero. Added a unit test for physical range normalization across generations.

Limitations: VICTORY_VUM_PHYSICAL=1 remains experimental and OFF by default. This is not a complete remapping solution. Closed native command lists embed GPU addresses and the THIN translator currently frees its source stream after translation, including commands with one-shot side effects. An obsolete closed recording cannot yet be safely regenerated; the experiment stops with a clear error rather than silently using the old data. Persistent descriptors used during translation can also hit this stop before the submission-time rebind. Dynamic descriptor tables, untracked GPU-address users, texture paths and GPU-indexed writes are not fully covered. This phase does not convert new allocations in the default configuration, nor claim a frame-rate gain. Next architecture step needs stable virtual GPU bindings or replay-safe source streams; D3D12 cross-adapter shared heaps cannot simply be assumed compatible with reserved resources. Windows build and runtime correctness not verified. Do not enable the experiment in the ordinary benchmark.
