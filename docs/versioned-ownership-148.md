# Build 0.148 — versioned ownership coverage

This phase makes the existing per-flight producer counts and CPU write journal the sources of truth for refresh ownership. Each Shadow keeps the exact declarations and a disjoint interval index of their union, updated under the pending lock. Releasing one producer does not release another's overlapping range. CPU refreshes visit only gaps in this coverage and skip gaps whose existing journal versions are already current. Whole requests can be certified current by CPU journal stamps even when GPU writes are pending, without claiming the CPU has the GPU result. Existing CPU-write-under-flight reconciliation, dirty sends, physical alias journal invalidation and relay/fence completion remain unchanged. A whole-range stamp can also establish the pre-landing version of a complete page of a copy, under the existing guarded landing checks.

This does not yet defer readbacks: title code runs natively and can directly load memory without an intercepted API. Delaying visibility past the established boundary needs a read interception or another proven guarantee. The coverage index is not physical allocation ownership across arbitrary aliases. No claim of measured FPS or unique traffic reduction: the GPU-owned coverage counter counts requested spans already excluded from CPU copying by the previous implementation, whereas clean gap requests are newly skipped checks, not physical bytes transferred.

Switch VICTORY_VERSIONED_OWNERSHIP=0 restores previous refresh decisions. Index maintained even with switch off. New log line: versioned ownership per frame. Unit test for overlapping declarations and release. Windows build and benchmark not run.
