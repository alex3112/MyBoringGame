# Build 0.150 — VUM 1 / dedicated native shared backing

A bounded first implementation, not a full UMA emulator. XMemAllocDefault owns a whole allocation's lifetime. For 1–64 MiB total allocations aligned up to 64 KiB, once the native D3D12 device already exists, try a SEC_COMMIT section, one CPU view, and one native D3D12 buffer over that section. The 256 MiB default charged budget is held until the last retained backing drops. No hardcoded title address. Driver rejection or allocation/budget failure falls back to the original 0.149 allocator. No private VirtualAlloc replacement, no bulk page-pool SEC_COMMIT, no address-pinned private heaps.

Registered buffers and loose windows fully contained in a dedicated allocation, and raw-address buffers fully contained in one, share the same native resource and use translated offsets. Logical bounds remain separate. Several native descriptor identities can resolve the same physical backing. A direct shared refresh holds the view for the recording but generates no refresh step. Declared shader writes retain the existing submission/fence dependency and completion order, with no snapshot/compare/copy-back: the bytes already reside in the CPU mapping. The completion notifies the old write journal/texture invalidation for other representations. CPU steps that depend on pending shared writes use the existing waits instead of card-step promotion. Freeing the CPU mapping removes the cached views; the section backing stays alive for retained GPU work. Old VICTORY_INPLACE is not enabled.

Limitations: remappable physical page-pool sections, arbitrary native VirtualAlloc memory, scattered mappings, ranges crossing dedicated allocation boundaries, textures, and private allocations created before host init are not converted. Dynamic shader writes not explicitly declared remain a correctness limitation (existing picked-write tracking is specific to carded copies). This is a new allocation backend, not retroactive conversion of live allocations; the 0.149 hot buffer's allocator has not been established. No guarantee of eligibility, driver performance, or FPS gain. Shared system memory has lower GPU bandwidth than local VRAM. Windows compilation and graphics correctness not verified. VICTORY_VUM=0 restores 0.149 allocation behavior; VICTORY_VUM_MB adjusts the charged cap (default 256 MiB, max 1024). New per-frame VUM line gives allocations, live/charged MiB, direct views and omitted refresh requests (logical bytes, not measured physical traffic).
