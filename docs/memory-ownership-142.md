# Build 0.142 — GPU memory ownership, phase 1

This is the first restricted ownership path, not a general lazy-readback implementation. A native GPU-to-GPU placed copy of at least 1 MiB between existing registered card-backed private buffers may omit its eager CPU mirror when the entire submission has no CPU consumer of its destination, conflicting CPU write, unknown callback, other native backing of that destination, overlapping copy, or in-flight conflict. The normal native copy and its declared GPU write are retained. The destination's exact Shadow and byte range are tracked with the flight until relay landing; subsequent CPU or alias-dependent work uses the established relay wait. All CPU-visible fences retain existing semantics, and all existing readbacks remain enabled. This can trade CPU copies for additional GPU readback if the GPU changes more bytes than the previous eager CPU mirror; no FPS or memory reduction is claimed without measurement. Physical page views and ambiguous cases fall back. The two existing GPU copy promotion paths are not combined in one submission. Switch: VICTORY_GPU_MEMORY_OWNERSHIP=0.

Card-dirty uploads now take a weak, per-resource clean-to-dirty queue instead of visiting the entire resident registry. The dirty-range and sent-version journals remain authoritative; taking and clearing is atomic under the resource lock, so a concurrent write is either taken now or requeued. No extra strong references or buffer allocations. Switch: VICTORY_DIRTY_RESOURCE_QUEUE=0.

Logs report candidates, GPU-owned copies, omitted CPU mirror bytes, dirty queue enqueues, visits, and uploads. The full physical alias ownership model, lazy CPU readbacks and native queue/fence split are future phases. No shader, game data, frame pacing, or resolution changes. Static review only; Windows compilation and the gameplay benchmark have not been run.
